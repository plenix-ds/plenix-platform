# The icon inventory

Candidate icons from other icon libraries, restyled to the Plenix icon guidance (`platform/standards/icons.md`). It is
separate from the working set (`../map.json` and the Material files beside it): apps draw nothing from here until the
owner approves an icon and it is added to the working set.

## Two kinds of icons, two rules

| | The working set (`platform/icons/`, `library/`) | The inventory (`platform/icons/inventory/svg/`) |
|---|---|---|
| What | Material Symbols Sharp, weight 300 | Icons from other open libraries, restyled |
| Files | Used exactly as Google publishes them | New Plenix drawings made by `tools/icons/restyle-icon.js` |
| Editing | Never edit, redraw, re-pad or re-weight | Restyled on purpose (owner, 2026-10-24); the library's original is kept beside it as `<icon>.found.svg` |
| Apps | Drawn today | Not drawn until approved |

The restyle tool refuses to write over the Material files.

## Files

| File | What |
|---|---|
| `libraries.json` | The 41 libraries the owner listed: source, license, status (downloaded, attribution, wrapper, local, decision) and why |
| `inventory.json` | One record per candidate: name, aliases, keywords, category, library, license, sizes, state, what it replaces, check results |
| `inventory.js` | GENERATED by `tools/icons/build-inventory.js`: the records with their drawings, for the design spec's Icon inventory page |
| `material-measure.json` | GENERATED by `tools/icons/measure-material.js`: the working set measured (the guidance's numbers) |
| `svg/<library>/<icon>.svg`, `-fill`, `-24`, `-24-fill` | The restyled drawings (viewBox `0 -960 960 960`) |
| `svg/<library>/<icon>.found.svg` | The library's original, unedited, for comparison |

## States

- `found`: picked from a library, not restyled yet.
- `restyled`: its four files exist and are checked; `check` records every file's result.
- `approved`: the owner chose it. Only then may it join the working set, through `map.json` and a release the owner
  declares.

A record's `replaces` names the working-set icon it would replace (Save: `save`). Such a replacement is a pixel change:
it waits for the owner's look at `docs/briefs/iconography/first-batch.html`.

## Adding a candidate

1. Copy the libraries locally once: `npm install --prefix tools/icons`, then `node tools/icons/fetch-libraries.js`
   (about 96,000 icons; the store is `C:/Users/Administrator/Documents/Plenix-icon-libraries`, outside git, with its
   `manifest.json`).
2. Find the icon in `<store>/<library>/<set>/svg/`. Check it as found: `node tools/icons/check-icon.js <file>`.
3. Add a record to `inventory.json` (`state: "restyled"`, `library`, `icon`, and `fillFrom` when the library has its own
   filled version).
4. `node tools/icons/build-inventory.js`: restyles, checks, and writes the results back. Fix or drop a record whose
   files fail.
5. Look at it: `docs/briefs/iconography/first-batch.html` (and `shoot.js` for a picture).

## Licenses

Every downloaded library allows use, change and redistribution (MIT, ISC, Apache-2.0, CC0-1.0). Keep each
library's license file with any icon taken from it (the store holds them). No library that needs a visible credit
line is used: Streamline was left out for that reason (owner, 2026-10-24). Logos and flags keep their brands' rules and
are never restyled.
