Plenix Data Grid Study

Which data grid engine should sit behind one Plenix DataGrid component, so every app gets the same grid instead of a table adjusted by hand each time.

Checked 2026-10-08 against each library's own docs, pricing pages and the npm registry · Plenix runs React 18.2, vendored, built without a bundler

The short answer

  1. The time sink is not the library; it is adjusting each grid by hand. The fix is one Plenix DataGrid component: one API, the plx theme, density, table lines and fonts set once. The engine underneath becomes replaceable.
  2. No free grid does all 12 of your needs. The drag-to-copy fill handle is the feature that splits free from paid almost everywhere.
  3. Recommended engine: Tabulator 6.6 (MIT, free). 11 of 12 out of the box, including grouping, tree rows, context menus, row and column drag and inline editing. It ships a plain script that exposes window.Tabulator, which fits the Plenix no-bundler build exactly. Missing: a drag fill handle (copy, paste and paste-to-fill over a range are included).
  4. If budget allows and you want every feature with no building: AG Grid Enterprise, $999 per developer (perpetual, 1 year of updates). Best CSS-variable theming of the group, but about 0.9 MB gzipped.
  5. Next step: a one-week spike in the spec, a Data grid page that drives Tabulator through all 12 features in the plx look, before anything goes into an app.

How each one fits Plenix

The features decide half of it. The other half is whether the engine accepts the Plenix rules: tokens only, no inline styles, Sans for UI and Mono for technical values, soft table lines, three densities, and a build that only knows React, ReactDOM and the Platform.

Three ways to go

Recommended

A. Plenix DataGrid on Tabulator

Free and the widest free coverage. Plenix wraps window.Tabulator in its own React component (the published React wrapper is abandoned and stuck on React 17), and ships one datagrid.css that maps plx tokens onto Tabulator's classes.

  • Gets: 11 of 12 today, built-in menus, grouping with totals, tree rows.
  • Gives up: a drag fill handle. Copy, paste and paste-to-fill cover most of it; a handle could be added later as a Plenix module.
  • Risk: theming by class overrides, not variables, so a Tabulator major version needs a visual check.
If budget allows

B. Plenix DataGrid on AG Grid Enterprise

All 12, including the fill handle, plus range selection, Excel export and set filters. Theming is the cleanest: plx tokens map one to one onto --ag-* variables.

  • Gets: everything, maintained by a company, strong accessibility.
  • Gives up: $999 per developer, and about 0.9 MB gzipped on every grid page.
  • Also possible: start on AG Grid Community (8 of 12) and buy Enterprise later without changing the Plenix API.
Most control

C. Plenix DataGrid on TanStack Table

Headless: TanStack keeps the state (sorting, filters, grouping, expansion, selection), Plenix draws everything with its own components. A perfect design fit, and no foreign stylesheet.

  • Gets: total control and the smallest download.
  • Gives up: weeks of work. Editing, drag and drop, the context menu, the fill handle, virtualization and the ARIA and keyboard model are all Plenix code to write and test.
  • Best if the grid itself becomes a Plenix product feature.

Ruled out, and why

react-data-grid
Needs React 19.2; Plenix runs 18.2. Strong otherwise (fill handle, grouping), so worth a second look if Plenix moves to React 19.
MUI X Data Grid
Needs Material UI and Emotion, a second design system next to plx. Grouping and fill handle are Premium ($599/dev/yr).
Handsontable
Commercial license for any commercial use; price only by quote. Spreadsheet-first, no select-all header.
Glide Data Grid
Canvas-drawn, so plx CSS cannot style it; last stable release February 2024. No sort, filter or grouping built in.
react-tabulator
Abandoned (August 2024), pins Tabulator 5, React 15–17. Plenix wraps Tabulator itself instead.
Grid.js · DataTables
Grid.js has no grouping, editing or menus. DataTables is jQuery-based; its Editor is paid.
Inovua ReactDataGrid
No release since July 2023; its repository is gone.
Not grid libraries
KumikoUI (.NET MAUI), CoreUI Smart Table (paid PRO), uiGrid (young AngularJS remake), Grist (a spreadsheet app), the Dash boilerplate (Python docs).

Proposed next steps

  1. Decide the engine (A, B or C) and whether the drag fill handle is a must or a nice-to-have.
  2. Spike, about one week: vendor the engine like React, wrap it as DataGrid, theme it with plx tokens at all three densities, and put a Data grid page in the spec that exercises all 12 needs on real Asset Manager data.
  3. Judge the spike against the plx table look (soft lines, gray header, label column) in light and dark, plus keyboard and screen reader checks.
  4. Adopt: one Plenix API (columns, rows, features on or off), its inventory record, then replace hand-built tables screen by screen, starting with the Asset Manager.
