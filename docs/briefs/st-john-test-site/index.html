St. John the Beloved test site: built, and the tests run there now (#338)

You asked for a "dummy site" that uses every page, control and component, so the tests stop running on the design spec. It is built: St. John the Beloved Coptic Orthodox Church, a church database and membership site with 35 pages. Every person, family and gift in it is made up. There are no sacrament records anywhere, and people who serve are called servants.

  • Where: test-site/, built by node build-app.js like the other apps. Open it at /Plenix/test-site/index.html.
  • Everything is used: all 388 Platform parts that draw something (components, patterns, page templates, providers and the hooks apps call) are in real use on the site. A new test (site coverage) fails if a new part is added to Plenix and not placed on the site.
  • The tests: every automatic browser test now opens the site and the suite apps, never the design spec. A full run takes about 24 minutes instead of about 5 hours.
  • The spec: nothing in the spec was changed. It is now only a consumer of the CDN (the Spec on the CDN session's work).

What the site found in Plenix (to fix in the Platform)

Real use turned up problems the spec's demos never showed. Each one is recorded in the test's known list, so the tests stay green now and fail if anything new appears.

  • Grid keyboard: a grid whose rows open on click puts every row in the Tab order, so the keyboard can't reach the page buttons under it (Directory, Families).
  • Header shortcut: the header search's own Ctrl K listener also takes Ctrl Shift K and is missing from the shortcut list. The site's command palette uses Ctrl Shift P for now.
  • ErrorPage takes no extra content (children or suggestions).
  • Time shows a date with no time ("2026-10-18") as the day before in US time zones.
  • Icon in a box: FeatureCard always draws an IconTile (an icon on a tinted square) unless it has a picture. This clashes with your no-icon-in-a-box rule.
  • Heading levels: Announcement (card) and ImageAnnotation always draw level 3 headings, with no option to change it.
  • Mono where it shouldn't be: CodeBlock's title and VersionCompare's prose lines are set in the Mono font. Chart data tables show dates in the normal font.
  • Lines out of step: ActivityList's time sits off its line.
  • Narrow screens: at phone width (320px), long Select options, TimePicker, MillerColumns and the page header's buttons stay too wide (16 pages listed).
  • Other gaps: EventChip has no orange or teal. A Wizard field marked as required shows the browser's popup instead of the Wizard's message.
  • Component tokens: 98 component token rules change nothing on the site, usually because a more specific rule always wins. They are listed in tests/baselines/component-tokens.json.
